## 全量包 [5.5] speedtest 编译失败修复
- 现象：`[speedtest] building target x86_64-pc-windows-msvc` 后报 `current directory is contained in a module that is not one of the workspace modules listed in go.work`，随后 Node `execFileSync` 抛错。
- 根因：`go env GOWORK` = `E:\go.work`（只 use `./ccworks/transkit`、`./newbosx`），项目 `E:\release\core` 在其目录树下但未被纳入 workspace，Go 1.25 因此拒绝在 core 模块里构建。
- 修复：`scripts/build-speedtest.mjs` 给 go 子进程加 `env.GOWORK = 'off'`，只用 core/go.mod。该 mjs 是全量包链路（build.bat → oneclick-build.ps1 [5.5] → build-speedtest-sidecar.ps1）、build-compile.bat、build-local.ps1、菜单 2 的唯一 Go 构建入口，改一处全覆盖；不动用户全局 `E:\go.work`。
- 验证：`go -C core list .` 原样报错，`GOWORK=off go -C core list .` 返回 `ThroneCore`；实际 `node scripts/build-speedtest.mjs` 成功生成 `src-tauri/sidecar/verge-throne-core-x86_64-pc-windows-msvc.exe`（EXIT=0）。
- 备注：`oneclick-build.ps1` 已含 `oneclick-build v6.1` 标记，build.bat 不会重新下载覆盖脚本。

## pre-commit biome 失败修复
- 现象：暂存区只有 `src/assets/styles/layout.scss` 时，husky → `cargo make pre-commit` → `pnpm exec lint-staged` 中 `biome format --write` 报 "No files were processed in the specified paths" 退出 1，提交被回滚。
- 根因：Biome 2.5.2 不支持/不识别 `.scss`（`biome.json` 的 `files.includes` 没问题，是扩展名被当作 unknown 忽略）；整批文件都被忽略时 biome 默认报错退出 1。
- 修复：`package.json` 的 lint-staged 两处 `biome format --write` 均加 `--no-errors-on-unmatched`（Biome CLI 自带参数，实测 2.5.2 有效），SCSS 仍跳过不格式化，其它文件照常格式化。已 `git add package.json` 一并暂存。
- 验证：`biome format --write --no-errors-on-unmatched <绝对/相对 .scss 路径>` EXIT=0；`pnpm exec lint-staged --no-stash` 完整跑通 EXIT=0（用 `--no-stash` 是为了避免与并发构建正在改写的 `tauri.conf.json` 冲突，未改动暂存区）。
